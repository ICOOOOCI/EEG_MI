# EEG_MI：个人运动想象采集与在线验证

当前目标是验证“真实 EEG 采集 → 个人校准 → 冻结模型 → 独立在线识别 → 有效期内输出”。程序使用真实 LSL 数据、因果滤波、CSP 对数功率特征和 LDA；不需要深度学习，也不包含产品 GUI。

**`main.py` 是唯一的项目运行时 Python 文件。** 设备预检、实验提示、采集、训练、回放、在线识别、安全检查和结果订阅都在这个文件中，通过子命令使用。

系统只支持**提示驱动的同步左右手控制**：收到 `MI_START` 后，在指定想象阶段判断左／右，每个试次最多产生一条方向指令。低置信度拒绝不等于识别休息状态。若要无提示、自发触发，需要另行采集无控制状态，并验证空闲误触发率。

**本轮没有设备或受试者，先完成软件和验收流程；软件测试通过不等于真人或设备验收通过。** 当前响应目标先定为提示到有效指令 **3–4 秒**。真实显示 onset、放大器延迟、佩戴接触质量、独立真人识别效果和重戴表现仍须按文末流程测量。

## 1. 环境与设备配置

代码要求 Python 3.10+。本机版本快照为 Python **3.10.11**、macOS arm64、pylsl **1.18.2**，实际加载的原生 liblsl 为 **1.17.7**；这些是本机检查结果，不是其他平台必须使用的组合。

在新的虚拟环境或干净检出中安装；已有项目环境无需删除。在每个终端激活同一个环境：

```bash
cd /Users/jim_liao/Downloads/EEG_MI
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.lock.txt
python -m pip check
python -c 'import platform, pylsl; print(platform.python_version()); print(pylsl.library_info())'
python main.py --help
```

`requirements.lock.txt` 固定六项直接依赖及当前环境必需的传递依赖。MNE 的基本安装依赖 matplotlib/Pillow，故保留；没有安装 PsychoPy、Qt 或可选 GUI 扩展。原生 liblsl 不由这个文件锁定。若 `pylsl` 无法加载库，应安装与操作系统、CPU 架构匹配的 liblsl，必要时将 `PYLSL_LIB` 指向该库的绝对路径，然后重新执行上面的检查。其他操作系统或 Python 版本需要重新检查依赖与原生库兼容性。

开启真实放大器的原始 EEG LSL 输出，再查看实际流：

```bash
python main.py inspect-lsl
```

下面的流名、通道清单和参考电极仅演示参数格式，必须替换成**已经核对的实际接线**。`--reference` 记录真实参考电极，不会执行重参考；`--channels` 是流中 CH1–CH16 的传输顺序。采样率取自实际流，配置命令不会修改放大器设置。

```bash
python main.py configure-lsl \
  --eeg-name YOUR_RAW_EEG_STREAM \
  --channels Fp1 Fp2 F3 F4 FC1 FC2 C3 C4 Cz CP1 CP2 P3 P4 Pz O1 O2 \
  --reference YOUR_ACTUAL_REFERENCE \
  --units uV \
  --output device.json
```

当前 `configure-lsl` 面向 16 通道设备。单位如已由设备可靠声明，可不传 `--units`；显式单位与已声明单位冲突会被拒绝。所有示例输出路径都要求不存在；重复采集请使用新的目录名。

## 2. 真实信号预检

保持自然静息、按实际实验位置佩戴，先运行至少 15 秒的预检：

```bash
python main.py preflight --config device.json \
  --eeg-name YOUR_RAW_EEG_STREAM --duration 15 \
  --output runs/preflight-T-01.json
```

报告检查接收速率、时间戳间隔、样本年龄、静默断流，以及逐通道的非有限值、平线、异常幅值、疑似饱和、工频和高频噪声。结果必须为 `ready`／“可以开始”；`needs_adjustment` 时先处理对应通道、单位、参考或传输问题，再重新预检。

接触质量只使用信号代理指标，**没有测量电极阻抗**；仍须使用放大器自己的阻抗／接触检查。坏通道策略是停止并纠正问题，不自动丢弃、插值或重新排序通道。在线质量异常会拒绝窗口并清除连续确认；断流后需重新建立稳定采集并完成滤波预热。门槛应根据实测设备核定，不能仅为让报告通过而放宽。

逐通道幅值、局部平线、RMS、工频／高频噪声和疑似饱和检查也应用于每个模型窗口的原始信号；训练、回放、在线使用相同门槛和通道顺序，任一通道失败会拒绝整个窗口。相关门槛写入设备配置，并以 `window_quality_limits` 随模型冻结；预检不能单独覆盖已配置的通道／时序门槛。`channel_quality.json` 是会话后的原始信号诊断，和评分报告中模型窗口的有效比例分别统计。

## 3. 两终端个人校准

实验程序生成左右手随机且逐组平衡的试次；随机种子控制类别顺序，每次运行使用新的 UUID 试次编号。它发送不含类别的 `MI_Markers`，并把真值写入独立的 `labels.jsonl`。采集器和在线分类器不会收到标签。

默认每组开始休息 3 秒，每次提示前休息 2 秒、想象时长取配置的 `imagery_seconds`，提示后休息 2 秒。可通过 `--run-rest-seconds`、`--rest-seconds`、`--inter-trial-seconds` 增加休息；组间休息不得短于配置的滤波预热时间。

**先启动终端 A。** 它会创建标记流并等待接收端，默认等待 120 秒。提示开始后，受试者观看终端 A，按提示想象运动并保持身体实际不动。

终端 A（提示源）：

```bash
cd /Users/jim_liao/Downloads/EEG_MI
source .venv/bin/activate
python main.py experiment --config device.json \
  --subject PERSON01 --session-id T --runs 2 \
  --trials-per-run 40 --seed 101 \
  --output runs/cue-T-01
```

终端 B（采集器，A 等待期间启动）：

```bash
cd /Users/jim_liao/Downloads/EEG_MI
source .venv/bin/activate
python main.py record --config device.json \
  --subject PERSON01 --session-id T \
  --eeg-name YOUR_RAW_EEG_STREAM \
  --output runs/capture-T-01
```

提示参数默认是 2 组、每组 20 个试次，即每组每类 10 个；上例使用每组 40 个，给质量拒绝留出余量。训练门槛是**每组每类至少 10 个有效、允许拟合的独立试次**，并至少有两组。10 是工程最低门槛，不能证明真人数据已经充分；根据疲劳情况安排休息，收集更多组与不同时间的校准数据通常更利于评估稳定性。一个试次产生多个重叠窗口，仍只算一个独立试次。

让实验正常到达 `SESSION_END`，等两个终端完成写盘。按 `Ctrl+C`、设备失联、标记中止或写盘错误产生的是不完整会话：提示程序尽力发送 `DISCONNECT` 并记录中止，不会自动重连续跑。保留记录用于排查，不能通过修改状态文件将其作为完整训练／验收数据。

采集源直接结束但缺少 `SESSION_END` 会作为失败处理。原始数据关闭后，清单先进入 `finalizing`；通道诊断、时间报告及摘要写完后才提交 `complete`。报告写盘失败同样会使会话失败。`processed_raw_samples` 只表示写入器处理过的样本，`raw_samples` 则按关闭后实际文件长度和完整 chunk 索引确认；`unconfirmed_accepted_samples` 明确记录尚不能确认保存的数据，不代表已持久化。这里不承诺突然断电后的磁盘持久性。

`MI_Markers` 只含 `kind` 和 `trial_id`。左右手类别仅在独立日志的 `MI_START.original_class` 中，1 为左手、2 为右手；各阶段日志与采集事件逐项核对。实验的 `manifest.json` 保存日程、受试者、配置哈希、完成次数和异常，这些元数据不能混入 `labels.jsonl`。

导入、审计、训练：

```bash
python main.py import-session \
  --session runs/capture-T-01 --labels runs/cue-T-01/labels.jsonl \
  --output runs/personal-T-01.npz

python main.py train runs/personal-T-01.npz \
  --model models/PERSON01-v1
```

训练报告包含逐组左右手有效试次、类别比例、专家标记、被拒绝及缺失窗口。默认有效类别比例上限为 2:1，拒绝试次和拒绝／缺失窗口比例上限均为 50%。不足时明确要求补采，并保存审计为 `models/PERSON01-v1.audit.json`，也可用 `--audit-output` 指定路径。不要用降低门槛代替真实补采。`--min-trials-per-class-per-run 2` 只适合明确的小型软件测试，不是推荐的真人设置。其他显式门槛参数为 `--max-class-ratio`、`--max-rejected-trial-fraction` 和 `--max-rejected-window-fraction`。

CSP 和 LDA 在每个训练折内拟合；整组留出验证，重叠窗口不会跨训练／验证组。阈值和连续确认次数只根据 T 校准数据选择，选择后的 CV 分数是内部开发指标，不是独立测试成绩。`E` 数据不能训练或选参。冻结模型保存滤波、窗口、通道顺序、参考、版本和依赖；后续回放、在线都使用这份配置。修改配置或模型后，应重新进行独立测试。

旧模型若缺少 `window_quality_limits` 或其质量策略与当前配置不一致，会明确拒绝加载。保留旧模型和原始记录，使用原校准 NPZ 重新训练到新的模型目录；不要手工补写模型清单或覆盖旧成果来绕过检查。

会话标识严格为 `T` 或 `E`，`TEST` 等以 T 结尾的名称不代表校准会话。模型保存函数和命令行都会拒绝已有目标目录。原始采集导入还要求接收、进入记录队列及确认保存的数量一致，并有唯一的成功 `SessionEnd` 收尾记录；缺少这些证据的旧记录会被明确拒绝，不会自动补成“完整”。

## 4. 冻结模型的独立真人在线测试

先重新预检。保持同一受试者，使用新的 E 会话、新的随机顺序和新的输出目录；不要根据这个 E 会话的成绩再调模型并继续称其为独立测试。

终端 A（先启动，提示时间参数来自冻结模型）：

```bash
python main.py experiment --config models/PERSON01-v1/manifest.json \
  --subject PERSON01 --session-id E --runs 2 \
  --trials-per-run 40 --seed 202 \
  --output runs/cue-E-01
```

终端 B：

```bash
python main.py live --model models/PERSON01-v1 \
  --subject PERSON01 --eeg-name YOUR_RAW_EEG_STREAM \
  --result-stream-name MI_Results \
  --output runs/live-E-01
```

正常结束后评分，评分使用这次在线运行实际产生的指令：

```bash
python main.py evaluate-live \
  --session runs/live-E-01 --labels runs/cue-E-01/labels.jsonl \
  --output runs/evaluation-E-01.json
```

在线评分会交叉核对实际运行摘要、冻结模型版本、结果流日志和事件日志；仅将配置中的模式改为 `live` 不足以证明在线运行。方向指令必须具有实际发布时刻、提示到发布前检查的时间和结果年龄。评分拒绝 NaN、无穷大及布尔值等无效时间测量，输出路径已存在时也会拒绝覆盖。

评分按冻结窗口日程计算 `expected_windows`，缺失的整个试次或部分窗口计入 `missing_windows` 和有效比例分母；重复或不在计划位置的窗口会被拒绝。零预测的有效窗口比例为 0，不能通过遗漏记录获得高比例。`wrong_command_trials` 统计每试次首条错误方向指令；已测得的发布延迟超出想象阶段、或结果年龄超出冻结上限，即使方向正确也计为错误。重复方向指令另列在稳定性统计中。

`label_alignment_verified` 只说明标签、试次编号和阶段序列对应；兼容字段 `alignment_verified` 也是这个含义。`physical_cue_alignment` 和 `actuator_latency` 明确为 `not_measured`。缺少发布时间测量时，离线仍可按样本位置评分，但 `output_timing_measurements_complete` 为假，不能据此宣称响应延迟通过验收。

需要离线诊断时，可另外导入同次 E 记录并回放；回放表现不能替代在线结果：

```bash
python main.py import-session \
  --session runs/live-E-01 --labels runs/cue-E-01/labels.jsonl \
  --output runs/personal-E-01.npz

python main.py replay runs/personal-E-01.npz \
  --model models/PERSON01-v1 --realtime \
  --output runs/replay-E-01
```

完成首次 E 测试后，取下并重新佩戴电极，或者另一天重新采集：保持模型目录不变，重新预检，再运行相同流程，改用 `cue-E-02`、`live-E-02`、种子 303 和新的评分文件。分别报告两次结果；重戴失败后若重新校准，必须保存新模型版本并收集新的独立 E 数据。

## 5. 结果订阅与响应时间

`live` 通过版本化 JSON 字符串流 `MI_Results` 发布结果，并写入会话目录的 `results.jsonl`。未来 GUI 和控制程序通过这个接口接入。在线启动后，可以在第三个终端观察：

```bash
python main.py subscribe --stream-name MI_Results --timeout 0.5
```

结果封装包含 `schema`（`mi-results-v1`）、`session_id`、单调递增的 `sequence`、`model_version`、`mode`、`type`、`issued_at`、`valid_for_seconds` 和 `payload`。`Prediction` 是遥测，只有 `Command` 的 `LEFT`／`RIGHT` 是方向事件。消费者应使用接收端时钟同步后的 LSL 时间戳，检查有效期、重复序号和重复试次；停止、失联、过期、阶段结束及无有效信号时返回 `NO_COMMAND`。订阅端必须保留自己的超时看门狗，不能无限保持最后一次方向。LSL 发布成功不等于下游设备执行成功；实际执行确认需要由下游记录。

`PreparedCommand` **仅写入本地审计日志，绝不通过 LSL 发送，也不是可消费的指令**。程序先完成这一步写盘，再重新检查信号、试次、阶段、结果年龄和停止状态，只有最终有效的 `Command` 才能发送；因此慢写盘不能使旧方向指令绕过检查。发送后再写入最终结果，若此时写盘失败，交付状态存在不确定性，会话会失败，消费者依靠有效期停止。日志读取程序同样必须忽略 `PreparedCommand`，不能仅看 `payload.direction` 执行动作。传输序号允许跳号。下游实际执行的 ACK 和完整执行延迟仍需另行记录。

默认窗口 2 秒、提示后偏移 0.5 秒、步长 0.2 秒：

```text
最早完整窗口：0.5 + 2.0 = 2.5 秒
连续 K 次满足判决条件：至少 2.5 + (K - 1) × 0.2 秒
若 K=3，理想最早为 2.9 秒，再加采集、传输、排队、推理和输出延迟
```

当前验收目标先按 **3–4 秒**设计，尚未用真人或物理链路证明达到。“每 0.2 秒更新”不是“0.2 秒响应”。实际以冻结模型中的参数为准，质量拒绝或置信度不足会延后乃至取消指令。推理完成后会再次检查窗口年龄、当前试次、想象阶段、信号新鲜度和停止状态，过期结果不得产生方向事件。

有效窗口及其方向指令中的 `timestamp` 是窗口内最后一个实际 EEG 采样的时间；`stop_sample` 仍是不包含在窗口内的结束索引。不能把这个索引边界当成一个尚未到达的采样时刻。推理前、推理后、写盘后的最终发送前都会检查有效性；停止后同一输入包中的后续窗口不会继续调用模型。

报告的 `cue_to_command_seconds` 来自采样索引；`cue_to_output_seconds` 到最终发送前安全检查为止，包含此前的排队、滤波、推理和写盘时间，**不包含发送完成或执行器 ACK**。源端测量和真实提示到执行的完整延迟必须分开报告。

## 6. 时间对齐与真实验收

终端提示在写入并 `flush` 返回后立即取 `pylsl.local_clock()`，同一时间戳写入独立标签并用于标记发送。这个时间对应软件提交提示，**不等于屏幕实际亮起时间**。源端写盘、发送时间及接收端统计只能说明软件链路的一部分；LSL 时钟同步也不替代显示 onset 或 EEG 放大器延迟测量。

标签中的 `marker_send_start`、`marker_send_end` 是源端发送调用起止时间。跨机器时，不能直接用源日志和接收日志的时间戳相减并称为对齐误差；必须先处理时钟域，并区分显示刷新、传输、时钟修正和 EEG 采样量化。

标记自身的传输年龄大于 EEG 缓冲宽限，不直接等于“迟到”：宽限从 EEG 包接收时刻开始计算，EEG 上游本身也可能有延迟。时间报告分别保留这些统计，真正已错过对应 EEG 的标记由采集器拒绝；宽限建议还会计入已测 EEG 数据年龄，不会自动修改冻结配置。

上线前保留以下实测记录，每项标注设备、采样率、通道配置、模型版本和日期：

- 使用光电二极管或与 EEG 共同采集的硬件触发，测量真实提示 onset 与 EEG 的偏差、抖动和分位数；据此核定时间戳容差、标记缓冲时间与最大数据年龄。
- 在独立 E 数据上报告试次分类正确率、平衡正确率、方向指令正确率、指令覆盖率、错误指令数、有效窗口比例；零指令不能被当作高准确率通过。
- 报告完整提示到指令发布、以及指令发布到下游实际执行的延迟分布。采集样本索引推导的提示延迟和单次模型计算时间，只能作为分段指标，不能冒充完整物理链路延迟。
- 在重戴／下一次采集后重复同样的冻结模型测试，单独比较稳定性。
- 验证设备断开、标记丢失／重复／迟到、慢推理、队列溢出、写盘失败和主动退出：方向输出停止，异常明确记录，可保存的数据完整落盘；写盘失败不可能保证尚未写出的数据持久化，应检查 manifest 中的计数和错误。
- 响应目标先按 3–4 秒执行；在真人测试之前，进一步明确统计口径（例如成功指令的第 95 百分位不超过 4 秒），以及可接受的正确率、覆盖率和错误指令上限并保存验收标准。该分位数口径是待确认的验收选项，不是已经取得的结果；不要看到测试结果后再改门槛。

当前工程尚不能替代上述真人与物理链路验收。预检为“可以开始”只表示当前信号通过配置的采集质量门槛，不表示模型已达到控制要求。
